# Production-readiness audit, 2026-11-14

Scope: the whole project on branch `design/windows-theme`, read-only. Four parallel audits (security and privacy, backend reliability and speed, tests/CI/release, frontend and UX) read the code. The most severe claims were then re-checked by hand against the source; those rows are marked **verified**. Nothing in this document has been fixed yet. It is the plan.

## What could not be done

- **Rust was not compiled or run.** This machine has no `cargo`. Rust findings come from reading the code. CI (`ci.yml`) is the only place the Rust tests run today.
- **No native window test.** Computer use is off, so no button in the real Tauri window was clicked.
- **No real model run.** Streaming, stop, and sidecar crash behaviour were judged from code.

## Verdict

Not ready for strangers yet. The structure is good, and most of the hard parts (sidecar isolation, verified downloads, encrypted backups, typed IPC) are done well. The blockers are a handful of unchecked paths at the IPC boundary, features that look finished but are not wired, a UI that freezes on long jobs, and a release pipeline that publishes unsigned builds with no update path.

| Area | Grade | Worst problem |
|---|---|---|
| Security and privacy | D | A bad model id can delete the whole data folder (SEC-01) |
| Features work end to end | C- | "Use this" does not load the model; chat fails until restart (UI-01) |
| Reliability | C | Indexing and model checks freeze the window (BE-01) |
| Release and operations | D | Public, unsigned releases with no checksums or updater (REL-01, REL-02, REL-04) |
| Code quality and tests | B- | Sidecar, cloud, download and every command have no tests |
| UI and design | B | Menus lack Escape and focus return (UI-14) |

## Plan

Each phase ends with the same gates: `npm run check`, `npm run build`, `npm test`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets` (CI, since this machine has no cargo), plus new tests for every fix.

| Phase | Goal | Items | Days | Changes behaviour |
|---|---|---|---|---|
| 0 | Stop data loss and fix broken features | SEC-01, SEC-02, SEC-03, SEC-04, SEC-07, SEC-25 (path checks); UI-02; UI-01 + UI-21; SEC-05; SEC-06; UI-07; BE-04 | 2 | Yes: model loads on "Use this", no launch-time network call, web search on Enter, one re-index |
| 1 | Never freeze, never orphan, always log | BE-01, BE-02, BE-03, BE-12, BE-13, BE-09, BE-08, BE-06, BE-07, BE-17, BE-11, BE-14, BE-19 + SEC-13 (atomic writes), REL-08 (single instance) | 4 | Little: a "loading model" state appears at startup |

| 3 | Speed and scale | BE-05, BE-10, BE-16, BE-15, BE-20, BE-21, SEC-18, BE-22, BE-25, BE-23 + REL-17, UI-19 | 4 | Little: better PDF text |
| 4 | Ship safely | REL-02 (signing), REL-01, REL-11, REL-04 (updater), REL-03, REL-20, REL-09, REL-06, REL-07, REL-18, REL-05, REL-10, REL-15, REL-16, REL-12, REL-13, REL-19, REL-21, REL-22 | 6 + certificate wait | Yes: installer identity and update prompt |
| 5 | Harden and test | SEC-08 to SEC-24 not yet covered, BE-24, test coverage gaps, REL-14, REL-24, docs truth (below) | 6 | Some: key re-entry on URL change, online opt-in |

Beta-ready after phases 0 to 2 (about 10 days). Public-ready after phase 4.

Risk: phase 4 needs paid signing certificates (Apple Developer and a Windows code-signing certificate), renewed yearly.

Note on REL-06: change the bundle identifier only if no public build has shipped yet. Changing it later breaks upgrades.

### Docs truth (phase 5)

The steering files under `.kiro/steering/` are stale:

- `tech.md` says `lib.rs` sets `#![allow(clippy::all, unused)]`. It does not.
- `tech.md` counts 16 `unwrap()`/`expect()` calls. The count is now 25 `expect` plus 1 `panic!`, and 0 `unwrap()`.
- `product.md` says hybrid search is keyword-only and embeddings are never written. The code now has an embedding sidecar, `embedding_backfill` and vector scoring. Re-verify end to end, then update.
- `structure.md` does not list `websearch`, `backup`, `skills`, `hf`, `cloud`, `embedding` or `rerank`.
- `product.md` says no update check is wired. `App.svelte` calls a GitHub release check on launch (SEC-06).
