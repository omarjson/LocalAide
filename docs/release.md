# Releasing LocalAide

This page explains how a release is built, what CI checks, and the steps that need a person: signing certificates.

## How a release is built

1. Bump one version in `package.json` (`node scripts/bump-version.mjs <new-version>` promotes the CHANGELOG's Unreleased section too). The `version-gate` job fails if a tag does not match it, or if CHANGELOG.md has no section for it.
2. Push a tag such as `v0.1.3`, or run the "CI & Release Pipeline" workflow by hand with "Create a draft GitHub Release" ticked.
3. CI builds the installers with electron-builder for macOS (Apple silicon and Intel), Windows (x64 and ARM64) and Linux (x64). The model engine is not in them: the app downloads the official llama.cpp build for the user's processor the first time a model loads ([ADR-0012](adr/0012-engine-download.md)).
4. The `publish-release` job makes a **draft** release with the installers, `SHA256SUMS.txt` and `localaide-sbom.spdx.json`. Nothing is public yet.
5. A person downloads the installers from the draft, tries them on a real machine, then presses "Publish".

To test the builds without a release, put `[build-all]` in a commit message on any branch.

## Build an installer on your own computer

CI builds every release, so this is only for trying a package locally.

You need:

- **Node.js 24 or newer.** No Rust and no C compiler — the backend is plain Node ESM and SQLite ships with Node.

Then, from the repository root:

```bash
npm ci
make dist   # vite build + electron-builder → release/
```

The app downloads its model engine on first use, so a local build needs nothing else. To try your own `llama-server`, set `LOCALAIDE_LLAMA_SERVER`… (not wired in this build yet — the engine path comes from `~/.aiassistant/tools/`).

The installers land in `release/`.

## What each release contains

| File | What it is |
|---|---|
| `LocalAide Setup <version>.exe`, `… arm64.exe` | Windows installers (NSIS) for x64 PCs and Windows on ARM |
| `LocalAide-<version>-arm64.dmg`, `LocalAide-<version>.dmg` | macOS disk images for Apple Silicon and Intel |
| `*.deb`, `*.AppImage` | Linux packages, built on Ubuntu 22.04 |
| `SHA256SUMS.txt` | SHA-256 of every file above. Check a download with `sha256sum -c SHA256SUMS.txt --ignore-missing` (Linux and macOS) or compare with `Get-FileHash <file>` (Windows). |
| `localaide-sbom.spdx.json` | Every npm package in the build, with versions and licenses |

Inside the app: `LICENSE`, `PRIVACY.md`, `TERMS.md` and `THIRD_PARTY_NOTICES.md`.

## CPU and runtime requirements

The model engine is llama.cpp build `b12359`, downloaded from github.com/ggml-org/llama.cpp with a pinned SHA-256 for each platform (`electron/services/download.mjs`), into `~/.aiassistant/tools/`. LocalAide picks the build for the processor itself, not for the app: an x64 app on Windows on ARM still gets the ARM64 engine. The x64 Windows and Linux builds carry a CPU library for each instruction set from SSE4.2 to AVX-512 and load the one the processor supports, so processors without AVX2 work too. The macOS builds use Metal.

Electron bundles its own Chromium, so there is no WebView2 dependency.

## Signing (needs certificates)

Unsigned builds work, but Windows SmartScreen and macOS Gatekeeper warn about them. electron-builder signs by itself when these repository secrets exist (Settings → Secrets and variables → Actions):

### macOS

| Secret | Value |
|---|---|
| `APPLE_CERTIFICATE` (`CSC_LINK`) | A "Developer ID Application" certificate exported as `.p12`, encoded as base64 |
| `APPLE_CERTIFICATE_PASSWORD` (`CSC_KEY_PASSWORD`) | The `.p12` password |
| `APPLE_ID`, `APPLE_PASSWORD`, `APPLE_TEAM_ID` | For notarization: the Apple ID, an app-specific password, and the team id |

This needs a paid Apple Developer membership.

### Windows

| Secret | Value |
|---|---|
| `WINDOWS_CERTIFICATE` (`CSC_LINK`) | A code-signing certificate, `.p12`/`.pfx` as base64 (or an Azure Trusted Signing configuration) |
| `WINDOWS_CERTIFICATE_PASSWORD` (`CSC_KEY_PASSWORD`) | The certificate password |

## Updates

The in-app "Check for updates" reads the GitHub releases API and links to the newest release page when one is newer than the running version. It reports `can_install: false` in this build: LocalAide cannot replace itself yet. electron-builder's GitHub publisher can provide signed auto-updates (`publish: github` is already configured); wiring `electron-updater` into the app is a planned port (ADR-0005's intent, carried over).

User data in `~/.aiassistant/` is not touched by an update or by uninstalling.

## Installer look

The Windows installer and the macOS disk image take their icon from `public/logo.svg` (the `build` section of `package.json`). Installer header/sidebar art generated by `scripts/gen-installer-art.mjs` lands in `build/installer/`.

## Bundle identifier

The identifier is `app.localaide.desktop` in the `build` section of `package.json`. Older Tauri installs used `com.localaide.app`; switching back would make an upgrade look like a different app to the OS.
